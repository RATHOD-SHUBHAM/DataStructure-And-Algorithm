Search in a rotated sorted array

LeetCode 33. At every step, one side of mid is a clean sorted run. Find it, check whether the target is inside it, then pick a side.

Step through it

Array [4, 5, 6, 7, 0, 1, 2], target:
sorted part at this step mid already ruled out

The three decisions per loop

  1. Find the sorted side. If nums[mid] > nums[right], the left part is sorted. Otherwise the right part is sorted.
  2. Check whether the target is inside that sorted side’s range.
  3. If it is, search that side. If not, search the other side.

The code

class Solution:
    def search(self, nums: list[int], target: int) -> int:
        left, right = 0, len(nums) - 1

        while left <= right:
            mid = left + (right - left) // 2

            if nums[mid] == target:
                return mid
            elif nums[mid] > nums[right]:
                # left part is sorted
                if nums[left] <= target < nums[mid]:
                    right = mid - 1
                else:
                    left = mid + 1
            else:
                # right part is sorted (includes mid == right)
                if nums[mid] < target <= nums[right]:
                    left = mid + 1
                else:
                    right = mid - 1

        return -1

Why the last branch is else, not elif

With while left <= right, there is a moment when left, mid and right are the same index, so nums[mid] == nums[right]. An elif nums[mid] < nums[right] is false then, no branch runs, nothing changes, and the loop never ends. Try target 3 above: the last step lands on exactly this case.

Rule for debugging: every path through a binary search loop must change left or right.
